## Finding and scope

The home route mounted its `SeoMetadata` on nested earthquake and cluster detail routes, so React could replace a server-rendered entity canonical with `/`. The earthquake and cluster wrappers also added `noindex` while detail JSON was loading. A temporary JSON failure could therefore change an otherwise verified crawler page's rendered robots metadata. [Google Search Central's JavaScript SEO guide](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) describes rendered metadata processing and warns that Googlebot may stop rendering after encountering `noindex`. This establishes a plausible failure mode, not the cause of an observed Search Console count.

Code commit `24b7b5acec4c4dcf8b384c30768c22dde1af0b3c` limits home metadata to `/`, preserves server title/canonical/robots during direct detail hydration and transient API failure, and starts unverified SPA detail routes with `noindex` and no inherited canonical. Exact-path markers are emitted only for verified 200 detail HTML, escaped by the Worker, and consumed once by the browser. Stored earthquake eligibility uses the same D1 magnitude/science predicate as the sitemap even when detail JSON comes from R2; below-threshold pages remain `noindex`. A missing D1 binding returns a retryable 503, including for archived detail. Missing and malformed detail routes remain `noindex`. The cluster wrapper applies the same exact-path verification without changing cluster sitemap eligibility.
